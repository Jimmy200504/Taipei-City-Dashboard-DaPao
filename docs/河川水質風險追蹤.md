# 河川水質風險追蹤：雙北 RPI 月份比例與測站地圖

## 資料

### 資料來源

本組件以「河川污染指數 RPI」追蹤雙北河川水質風險。RPI 以溶氧量 (DO)、生化需氧量 (BOD5)、懸浮固體 (SS)、氨氮 (NH3-N) 四項計算得出，雙北兩個資料源都涵蓋這四項，可作為一致比較基準。

| 城市 | 來源 | URL | 格式 | 用途 |
|------|------|-----|------|------|
| 臺北市 | 臺北市政府環境保護局河川水質檢測 | https://data.taipei/dataset/detail?id=759db528-77b5-4aa3-b6fa-2b857890214e | 開放資料 API（JSON/CSV） | 臺北市測站逐期測項 |
| 新北市 | 新北市政府環境保護局河川水質監測表 | https://www.epd.ntpc.gov.tw/FileListYearVersion/rv-w-mtg | 月報 PDF | 新北市測站逐月測項 |

臺北市資料透過 data.taipei API 取得結構化 JSON。新北市資料以月為單位釋出 PDF，檔案命名規則類似 `115年度新北市河川水質監測表－2月份.pdf`，每月一份。ETL 需爬取列表頁、下載新發 PDF、解析表格欄位，再寫入長表。資料內容時間優先使用採樣日期；若 API 或 PDF 提供資料更新時間，亦須保留至 ETL metadata。

### 欄位解讀

#### 臺北市 API

API 回傳之原始欄位通常為中文：`河川名稱`, `監測站`, `採樣日期`, `水溫`, `pH`, `溶氧量`, `生化需氧量`, `氨氮`, `懸浮固體`, `化學需氧量`, `總磷`, `濁度`, `大腸桿菌群`，以及部分重金屬欄位。資料為 wide format，每列一筆採樣，多個測項在同一列。

座標若 API 中無，需 join 環境部河川水質測點基本資料 (`WQX_P_06`) 或自維護對照表補齊。RPI 所需的 DO、BOD5、SS、NH3-N 直接由 `溶氧量`、`生化需氧量`、`懸浮固體`、`氨氮` 四欄取得。臺北市同月可能有多次採樣，月度聚合時取算術平均。

#### 新北市 PDF

PDF 表頭包含：

| 欄位 | 說明 |
|------|------|
| `河川名稱` | 河川中文名稱 |
| `監測站名稱` | 測站中文名稱，例如 `靈山宮`、`小石板橋` |
| `監測站編號` | `R01` ~ `R50`，新北市自編 |
| `水體分類等級` | `甲`、`乙`、`丙`、`丁`、`無` |
| `採樣日期` | 月/日，例如 `2/2`，搭配檔名年份還原為西元日期 |
| `採樣時間` | `HH:MM` |
| `氣溫`、`水溫` | 攝氏 |
| `水流量` | CMS，多數列為 `-` |
| `溶氧量`、`生化需氧量`、`懸浮固體`、`化學需氧量` | mg/L，RPI 主要來源 |
| `pH值`、`導電度`、`大腸桿菌群`、`濁度`、`總磷`、`氯鹽`、`總汞`、`硒` | 各自單位 |
| `硫酸鹽`、`氨氮`、`鉛`、`總鉻`、`六價鉻`、`鐵`、`錳`、`鎘`、`銅`、`鋅`、`砷`、`銀`、`鎳` | mg/L（續表）|

PDF 註記規則：

- `<X`：低於方法偵測極限值 (MDL)，X 為 MDL 數值，例如 `<0.003`。
- `@X`：高於 MDL 但低於檢量線最低濃度，X 為檢量線最低濃度值，例如 `@0.002`。
- `-`：未檢測或無資料。

ETL 解析時以正規表達式分離前綴 (`<`, `@`) 與數值，將原始字串保留至 `raw_item_value`，數值寫入 `item_value_numeric`，並寫入 `quality_flag`：

| `quality_flag` | 規則 |
|----------------|------|
| `normal` | 純數值 |
| `below_mdl` | 前綴 `<` |
| `below_loq` | 前綴 `@` |
| `not_measured` | `-` 或空白 |

新北市 PDF 不含座標，需以 `監測站編號` join 既有測站清單或環境部測點基本資料補齊 `wkb_geometry`。第一版若無法 join，仍可依編號維護一份對照表並標記 `geometry_source`。

### RPI 計算

RPI 使用環保署四項指標分數平均：

| 指標 | 未受污染 (1 分) | 輕度 (3 分) | 中度 (6 分) | 嚴重 (10 分) |
|------|----------------|------------|------------|--------------|
| 溶氧量 DO (mg/L) | > 6.5 | 4.6 ~ 6.5 | 2.0 ~ 4.5 | < 2.0 |
| 生化需氧量 BOD5 (mg/L) | < 3.0 | 3.0 ~ 4.9 | 5.0 ~ 15 | > 15 |
| 懸浮固體 SS (mg/L) | < 20 | 20 ~ 49 | 50 ~ 100 | > 100 |
| 氨氮 NH3-N (mg/L) | < 0.5 | 0.50 ~ 0.99 | 1.0 ~ 3.0 | > 3.0 |

`rpi_value = (do_score + bod_score + ss_score + nh3_score) / 4`

風險等級分級：

| `risk_level` | `risk_level_order` | 規則 |
|--------------|--------------------|------|
| `unpolluted` | 1 | rpi_value ≤ 2.0 |
| `mild` | 2 | 2.0 < rpi_value ≤ 3.0 |
| `moderate` | 3 | 3.0 < rpi_value ≤ 6.0 |
| `severe` | 4 | rpi_value > 6.0 |

若四項中有任一項為 `not_measured`，該月該測站 RPI 不計算，並以 `rpi_flag='incomplete'` 標記，不進入比例長條圖統計，但仍可在地圖以灰色顯示。`below_mdl` 取 MDL 值代入計算；`below_loq` 取檢量線最低濃度代入計算，並記錄於 `rpi_flag='complete_with_estimate'`，供 AI tooltip 說明。

## 前端

### 前端儀表板

前端儀表板支援 `臺北市` 與 `雙北` 城市範圍切換。切換城市範圍時，所有圖表依 `city_scope` 重新查詢或切換資料。

| 圖表 | query type | chart type | 顯示欄位 | 說明 |
|------|------------|------------|----------|------|
| 月份 RPI 風險比例長條圖 | `percent` | `BarPercentChart` | `x=sample_month`, `series=risk_level`, `y=site_count` | 每個月一列，依風險等級顯示測站比例（多少比例的測站 RPI 落於各區間） |
| 高風險測站排名 | `two_d` | `BarChart` | `x=site_name`, `y=rpi_value` | 最新月份 RPI 由高至低 |
| 測站 RPI 趨勢 | `time` | `TimelineSeparateChart` | `x=sample_month`, `y=rpi_value` | 單一測站 RPI 時間序列 |
| 異常測項分布 | `two_d` | `DonutChart` 或 `BarChart` | `x=item_name`, `y=abnormal_count` | 最新月份各測項超標次數 |

風險等級固定 series：`unpolluted`, `mild`, `moderate`, `severe`。即使某月某等級為 0，仍需回傳 `0`，避免 `BarPercentChart` 缺少 series。`percent` 查詢需依 `sample_month`, `risk_level_order` 排序，讓後端解析 categories 與 series 時保持穩定。

時間範圍以最新 12 ~ 24 個月為主；切換為 `雙北` 時，分母為臺北市與新北市測站合計，比例自動依 `city_scope` 範圍內的有效測站總數歸一化（`rpi_flag='incomplete'` 不計入分母）。

### 前端地圖圖層

前端地圖以「測站點 + 河流漸層線」呈現 RPI 空間分布：

- 測站點圖層：每個測站為一個點，顏色依最新月份 `rpi_value` 對應 `risk_level` 色階；`rpi_flag='incomplete'` 以灰色顯示資料不足。色階建議由淺至深對應 `unpolluted` → `severe`。
- 河流漸層線圖層：每條河川依其上下游測站之 `rpi_value` 沿線性內插上色，形成兩測站間的漸層；最上游或最下游延伸段以最近測站值漸淡，避免推估範圍過大。

切換為 `臺北市` 時，僅顯示臺北市測站與其所屬河流線段；切換為 `雙北` 時，同時顯示雙北測站與河流線段。地圖座標系統為 WGS84/EPSG:4326。

地圖點擊測站後，彈跳資訊顯示：

- 測站名稱：`site_name`
- 城市與行政區：`city`、`district`
- 流域與河川：`basin`、`river`
- 採樣月份：`sample_month`
- RPI 值與風險等級：`rpi_value`、`risk_level`
- 四項子指標：DO、BOD5、SS、NH3-N 之數值與分數
- 主要異常測項：`main_abnormal_item`
- 資料時間：`data_time`
- 資料來源：`source_name`（`臺北市` 或 `新北市`）

地圖點擊河流段後，彈跳資訊顯示該段上下游兩測站名稱與其 RPI 值，並標註「此段為上下游測站線性內插結果」。若測站缺座標，該測站不得進入地圖圖層，但仍可進入比例長條圖統計。

## 後端

後端需提供前端儀表板與地圖圖層兩類資料：時間序列比例圖表資料與測站點 + 河流漸層線地圖資料。圖表資料走既有 component chart query 流程，地圖圖層資料走 component map config 與 map query 流程。

### 月份 RPI 風險比例長條圖

```sql
SELECT
  sample_month AS x_axis,
  risk_level   AS y_axis,
  site_count   AS data
FROM env_river_rpi_monthly_distribution
WHERE city_scope = $1
  AND sample_month >= $2
ORDER BY sample_month, risk_level_order;
```

此查詢使用 `percent`，前端圖表使用 `BarPercentChart`。

### 高風險測站排名

```sql
SELECT site_name AS x_axis, rpi_value AS data
FROM env_river_site_rpi_monthly
WHERE sample_month = (
        SELECT MAX(sample_month) FROM env_river_site_rpi_monthly
      )
  AND city = ANY($1)
  AND rpi_flag IN ('complete', 'complete_with_estimate')
ORDER BY rpi_value DESC
LIMIT 10;
```

### 測站 RPI 趨勢

```sql
SELECT sample_month AS x_axis, rpi_value AS data
FROM env_river_site_rpi_monthly
WHERE site_id = $1
  AND rpi_flag IN ('complete', 'complete_with_estimate')
ORDER BY sample_month;
```

### 地圖圖層資料

測站點：

```sql
SELECT
  site_id,
  site_name,
  city,
  district,
  basin,
  river,
  sample_month,
  rpi_value,
  risk_level,
  rpi_flag,
  do_value, bod_value, ss_value, nh3_value,
  do_score, bod_score, ss_score, nh3_score,
  main_abnormal_item,
  source_name,
  data_time,
  ST_AsGeoJSON(wkb_geometry)::json AS geometry
FROM env_river_site_rpi_monthly_latest
WHERE
  CASE
    WHEN $1 = 'taipei'     THEN city = '臺北市'
    WHEN $1 = 'twin_city'  THEN city IN ('臺北市', '新北市')
  END
  AND wkb_geometry IS NOT NULL;
```

河流漸層線：

```sql
SELECT
  river,
  segment_id,
  upstream_site_id,
  downstream_site_id,
  upstream_rpi,
  downstream_rpi,
  sample_month,
  ST_AsGeoJSON(wkb_geometry)::json AS geometry
FROM env_river_rpi_segments_latest
WHERE
  CASE
    WHEN $1 = 'taipei'     THEN city = '臺北市'
    WHEN $1 = 'twin_city'  THEN city IN ('臺北市', '新北市')
  END;
```

`upstream_rpi` 與 `downstream_rpi` 提供前端做沿河段的線性漸層；若任一端 RPI 缺值，前端以灰色顯示該段。

建議資料表：`env_river_rpi_monthly_distribution`

| 欄位 | 型別 | 說明 |
|------|------|------|
| `city_scope` | text | `taipei` 或 `twin_city` |
| `sample_month` | date | 月份 |
| `risk_level` | text | `unpolluted`、`mild`、`moderate`、`severe` |
| `risk_level_order` | integer | 圖表排序 |
| `site_count` | integer | 該月該等級的測站數（僅統計 `rpi_flag` 為 `complete` 或 `complete_with_estimate`） |
| `site_ratio` | numeric | 該月內比例，可供 AI 或 tooltip 使用 |
| `total_sites` | integer | 該月有效測站總數 |
| `data_time` | timestamptz | 資料內容時間 |

聚合規則：

- `site_count` 以去重後 `(source_name, site_id)` 計算。
- 同一月內，每個測站取一筆代表性 RPI（多次採樣以四項月平均後再計分，而非分數平均）。
- 所有月份與所有風險等級都需補 `0`，確保比例長條圖資料完整。
- `taipei` 範圍只包含臺北市測站；`twin_city` 範圍同時包含臺北市與新北市測站。
- `rpi_flag='incomplete'` 的測站不計入分母，避免缺項干擾比例。

建議資料表：`env_river_rpi_segments_latest`

| 欄位 | 型別 | 說明 |
|------|------|------|
| `city` | text | 城市 |
| `basin` | text | 流域 |
| `river` | text | 河川 |
| `segment_id` | text | 段 ID |
| `upstream_site_id` | text | 上游測站 ID |
| `downstream_site_id` | text | 下游測站 ID |
| `upstream_rpi` | numeric | 上游測站最新 RPI |
| `downstream_rpi` | numeric | 下游測站最新 RPI |
| `sample_month` | date | 月份 |
| `data_time` | timestamptz | 資料內容時間 |

河段建立邏輯：以同河川內的測站依上下游空間順序配對，建立連續的相鄰測站段。河流幾何來源建議使用既有河川圖資（環境部或內政部開放資料）裁切為兩測站間的子線。第一版若河川幾何難以取得，可先以「兩測站直線連線」近似，並在地圖標註「直線示意」與 `geometry_source='straight_line'`。

### 資料更新與 metadata

ETL 每次更新後需同步更新 `dataset_info`。測站基本表與河流漸層段表支援地圖圖層，`dataset_info` 的 geometry 類型分別為 `Point` 與 `LineString`，座標系統為 `EPSG:4326`。長表測項表、月度 RPI 表與月度比例聚合表不需 geometry，但需保留資料來源、更新頻率、資料時間與 ETL 說明。

兩個資料源的更新頻率與接取方式：

- 臺北市：data.taipei API，每日排程，但實際監測為月或週為單位，需以採樣日期判定新增資料。
- 新北市：每月新發 PDF，需爬取列表頁、下載新增檔案、解析後寫入；建議以檔名年月作為冪等鍵。

ETL 失敗時保留前一版本資料，並在 `dataset_info` 標記 `last_success_time` 與 `last_attempt_time`。新北市 PDF 解析需保留原始 PDF 路徑或 URL，便於人工覆核 `<` 與 `@` 註記是否正確分離。

## AI Chat 的結合方法

AI Chat 透過後端 tool calling 整合本組件，不直接讓前端呼叫資料庫。建議提供以下 tools：

| Tool | 參數 | 回傳 | 用途 |
|------|------|------|------|
| `get_river_rpi_summary` | `city_scope` | 最新月份各風險等級測站數與比例、最高 RPI 測站、資料時間 | 回答整體水質風險概況 |
| `get_river_rpi_monthly_distribution` | `city_scope`, `start_month`, `end_month` | 各月各風險等級測站數與比例 | 供 AI 解釋月份 RPI 風險比例長條圖 |
| `get_river_site_rpi_trend` | `site_id`, `month_count` | 該測站近期 RPI 與四項子指標時間序列 | 供 AI 解釋單一測站趨勢 |
| `get_river_site_detail` | `site_id` | 測站基本資料、最新 RPI、四項數值與分數、主要異常測項 | 供地圖點擊或單站詢問 |
| `set_river_water_view` | `city_scope`, `focus_river`, `focus_site_id`, `focus_month` | 前端視圖控制指令 | 讓 AI 協助切換臺北/雙北、聚焦河川、測站或月份 |

Tool 參數規則：

- `city_scope` 只允許 `taipei` 或 `twin_city`。
- `site_id` 必須是 `env_river_monitoring_sites.site_id`，並配合 `source_name` 區分臺北市與新北市同編號測站。
- `focus_month` 為 `YYYY-MM` 格式。
- `start_month`、`end_month` 缺省時取最近 12 個月。

AI 回答需附帶資料時間與資料來源，並在資料缺漏時明確說明限制。例如某測站當月因氨氮缺值而 `rpi_flag='incomplete'` 時，AI 應指出該月該測站不參與比例統計；新北市 PDF 解析失敗或欄位不齊時，AI 應提醒使用者該月新北市資料不完整；若 RPI 是以 `below_mdl` 或 `below_loq` 代入估算，AI 應在 tooltip 註明 `complete_with_estimate`。
