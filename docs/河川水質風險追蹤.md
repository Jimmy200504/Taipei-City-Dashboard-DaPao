# 河川水質風險追蹤：雙北 RPI 測站地圖

## 資料

### 資料來源

本組件以「河川污染指數 RPI」追蹤雙北河川水質風險，並在地圖上以漸層折線呈現相鄰測站之間沿真實河道的污染程度變化。資料來源共兩個：環境部負責測站與 WQ_Index，水利署負責河川中心線幾何。

| 來源 | URL | 格式 | 用途 |
|------|-----|------|------|
| 環境部水質監測 GIS | `https://wq.moenv.gov.tw/EWQP_GIS/dataFile/AJAX_Main.aspx?Type=Get_point_WQStation_River` | JSON（AJAX 回傳） | 全國河川測站基本資料、最新月份 WQ_Index、風險分級 |
| repo curated river routes（derived from OpenStreetMap waterway centerlines） | `env_river_water_quality/assets/river_segment_routes.geojson` | GeoJSON LineString | 主要河川測站對的人工檢核 route 幾何，供 ETL 優先套用 |
| 經濟部水利署 河川河道（河川支流線） | `https://gic.wra.gov.tw/gis/gic/API/Google/DownLoad.aspx?fname=RIVER&filetype=SHP` | ZIP / ESRI Shapefile（`river.shp`，53,497 條 LineString） | route asset 未涵蓋時的備援河川中心線幾何 |

上述來源皆為公開資料，**不需** API key。Route asset 由 OpenStreetMap waterway centerline 擷取後人工檢核，授權依 ODbL；WRA shapefile 採 TWD97 / EPSG:3826，ETL 內重投影至 EPSG:4326；data-built 年份為 2000，對於雙北主要河川仍作為備援來源。WRA 授權：政府資料開放授權條款-第 1 版。

WRA 河川名稱與 MOENV `River_Name` 多數一致；少數別名於 ETL 內以對照表處理：

| MOENV `River_Name` | WRA `NAME` |
|--------------------|------------|
| 淡水河本流 | 淡水河 |
| 三峽河 | 三峽溪 |

### 資料缺漏（Lacked Data）

此端點僅回傳每個測站「最新一個月」的整體 WQ_Index 與分級結果，不含子指標數值與其他測項。下列項目本端點不提供，因此本組件**不**呈現對應功能：

1. **歷史月份**：僅有 `MonthDate_Dec` 一個月份欄位，無法繪製多月趨勢或月份比例長條圖。
2. **四項子指標數值**：DO、BOD5、SS、NH3-N 的原始 mg/L 值與各自分數均不提供，無法在 tooltip 顯示子指標、亦無法重算 RPI。
3. **其他測項**：pH、導電度、大腸桿菌群、濁度、總磷、重金屬等均不提供，「異常測項分布」圖無法建立。
4. **採樣日期與時刻**：僅有年月（例 `2026 年 3 月`），無採樣日期與 `HH:MM`。
5. **品質註記**：無 `<MDL`、`@LOQ`、`-` 等檢測極限標註。
6. **河川中心線幾何**：MOENV 端點僅含測站點位。本組件改以水利署 `river.shp` 補齊真實河道折線；ETL 將每個測站投影到最近的 WRA 河川支流線特徵，同特徵之測站對使用 `shapely.ops.substring` 切出真實河道段，跨特徵時以兩特徵之最近端點橋接。若某條河川在 WRA 圖資中找不到對應名稱、測站投影距離 > 1500 公尺、或橋接無法構成有效折線，則退回直線連線（`geometry_source='straight_line'`）。WRA `river.shp` 為 2000 年圖資且為碎片化資料（雙北 8 條河共數百條 LineString，無法 `linemerge` 為單一連續線），因此典型結果約 60% 段為實際河道幾何，其餘為直線退場。
7. **主要異常測項**：需由各測項超標判定，本端點無此資訊。

| `Town_Cname` | `district` | 行政區 |
| `Basin_Name` | `basin` | 流域 |
| `River_Name` | `river` | 河川 |
| `Station_Address` | `site_address` | 地址 |
| `測站使用狀態` | `status_of_use` | 啟用狀態 |
| `Wqstd_Name` | `wq_std_grade` | 水體分類等級（甲/乙/丙/丁/戊 或 A/B/C/D/E） |

| `Gis_Y` | `latitude` | WGS84 十進位緯度 |

### RPI 與風險分級

`rpi_value` 直接取自 `WQ_Index`，**不**重新以四項子指標計算。`risk_level` 由 `WQ_Index_Dec` 對應：

| `WQ_Index_Dec`（原文） | `risk_level` | `risk_level_order` | 說明 |
|-----------------------|--------------|--------------------|------|
| 未（稍）受污染 | `unpolluted` | 1 | 入圖表分母、地圖以對應顏色顯示 |
| 輕度污染 | `mild` | 2 | 同上 |
| 中度污染 | `moderate` | 3 | 同上 |
| 嚴重污染 | `severe` | 4 | 同上 |
| 無檢測資料 | `incomplete` | — | 不入圖表分母；地圖以灰色顯示資料不足 |

`rpi_flag` 僅有兩種值：

| `rpi_flag` | 規則 |
|------------|------|
| `complete` | `WQ_Index` 為有效數值 |
| `incomplete` | `WQ_Index_Dec = 無檢測資料` 或 `WQ_Index` 缺值 |

## 前端

### 前端儀表板

前端儀表板支援 `臺北市` 與 `雙北` 城市範圍切換。切換城市範圍時，圖表依 `city_scope` 重新查詢。

| 圖表 | query type | chart type | 顯示欄位 | 說明 |
|------|------------|------------|----------|------|
| 高風險測站排名 | `two_d` | `BarChart` | `x=site_name`, `y=rpi_value` | 最新月份 RPI 由高至低，預設 Top 10 |
| 風險等級分布 | `two_d` | `DonutChart` | `x=risk_level`, `y=site_count` | 最新月份各風險等級的測站數（單月快照，非時間序列） |

風險等級固定 series：`unpolluted`、`mild`、`moderate`、`severe`。即使某等級為 0，仍需回傳 `0`。`incomplete` 不入分母。

### 前端地圖圖層

前端地圖以「測站點 + 河流漸層線」呈現 RPI 空間分布：

- **測站點圖層**：每個測站為一個點，顏色依最新 `rpi_value` 對應之 `risk_level` 色階；`rpi_flag='incomplete'` 以灰色顯示資料不足。色階建議由淺至深對應 `unpolluted` → `severe`。
- **河流漸層線圖層**：ETL 優先使用 repo 內維護的測站對河道 route GeoJSON，將相鄰測站對對應到人工檢核過的河道折線，並標記 `geometry_source='curated_route'`。若 route asset 未涵蓋該測站對，才退回 WRA 河川支流線投影：同特徵之相鄰測站使用 `shapely.ops.substring` 切出實際河道段，跨特徵時以兩特徵最近端點橋接，標記 `geometry_source='real_river'`。任一測站投影距離超過 1500 m、找不到對應 WRA 河川、或橋接失敗時，最後退回 `geometry_source='straight_line'`。沿線以 `upstream_rpi` → `downstream_rpi` 線性內插上色。

切換為 `臺北市` 時僅顯示臺北市測站、且兩端皆位於臺北市的河段；切換為 `雙北` 時同時顯示雙北測站與所有河段（包含跨市段）。測站點圖層只匯出該城市範圍內可見河段的端點，避免顯示沒有對應河段的孤立測站點。地圖座標系統為 WGS84/EPSG:4326。

地圖點擊測站後，彈跳資訊顯示：

- 測站名稱：`site_name`
- 城市與行政區：`city`、`district`
- 流域與河川：`basin`、`river`
- 水體分類等級：`wq_std_grade`
- 採樣月份：`sample_month`
- RPI 值與風險等級：`rpi_value`、`risk_level`
- 資料時間：`data_time`
- 資料來源：`source_name = '環境部'`

若測站缺座標（`Gis_X` 或 `Gis_Y` 為空），該測站不進入地圖圖層。

## 後端

後端提供兩種圖表查詢與兩個地圖圖層查詢（測站點、河流漸層段），分別讀取最新快照表與漸層段表。

### 高風險測站排名

```sql
SELECT site_name AS x_axis, rpi_value AS data
FROM env_river_site_rpi_latest
WHERE
  CASE
    WHEN $1 = 'taipei'    THEN city = '臺北市'
    WHEN $1 = 'twin_city' THEN city IN ('臺北市', '新北市')
  END
  AND rpi_flag = 'complete'
ORDER BY rpi_value DESC
LIMIT 10;
```

### 風險等級分布

```sql
SELECT risk_level AS x_axis, COUNT(*)::int AS data
FROM env_river_site_rpi_latest
WHERE
  CASE
    WHEN $1 = 'taipei'    THEN city = '臺北市'
    WHEN $1 = 'twin_city' THEN city IN ('臺北市', '新北市')
  END
  AND rpi_flag = 'complete'
GROUP BY risk_level, risk_level_order
ORDER BY risk_level_order;
```

### 測站點圖層

```sql
SELECT
  site_id,
  site_name,
  city,
  district,
  basin,
  river,
  wq_std_grade,
  sample_month,
  rpi_value,
  risk_level,
  rpi_flag,
  source_name,
  data_time,
  ST_AsGeoJSON(wkb_geometry)::json AS geometry
FROM env_river_site_rpi_latest
WHERE
  CASE
    WHEN $1 = 'taipei'    THEN city = '臺北市'
    WHEN $1 = 'twin_city' THEN city IN ('臺北市', '新北市')
  END
  AND wkb_geometry IS NOT NULL;
```

### 河流漸層段圖層

```sql
SELECT
  segment_id,
  river_id,
  river,
  basin,
  upstream_site_id,
  upstream_site_name,
  upstream_city,
  upstream_rpi,
  downstream_site_id,
  downstream_site_name,
  downstream_city,
  downstream_rpi,
  sample_month,
  geometry_source,
  data_time,
  ST_AsGeoJSON(wkb_geometry)::json AS geometry
FROM env_river_rpi_segments_latest
WHERE
  CASE
    WHEN $1 = 'taipei'    THEN upstream_city = '臺北市' AND downstream_city = '臺北市'
    WHEN $1 = 'twin_city' THEN TRUE
  END
  AND wkb_geometry IS NOT NULL;
```

`upstream_rpi` 與 `downstream_rpi` 供前端沿 `geometry` 做線性漸層；`geometry_source='straight_line'` 時建議在前端 tooltip 加註「此段為直線示意」以區分。

## 資料端邏輯

ETL 從 MOENV AJAX 端點抓取 JSON，篩選 `County_Name IN ('臺北市', '新北市')`，標準化欄位名稱；同時下載並快取（7 天 TTL）水利署 `river.shp`，將相鄰測站投影到對應河川中心線並切出漸層段。最終寫入三張表：測站基本表、最新快照表、河流漸層段表。每次 ETL 以 `(site_id)` 與 `(segment_id)` 為冪等鍵覆寫最新快照表與漸層段表。

### 測站基本表

建議資料表：`env_river_monitoring_sites`

| 欄位 | 型別 | 說明 |
|------|------|------|
| `source_name` | text | 固定為 `環境部` |
| `city` | text | 城市（`臺北市` 或 `新北市`） |
| `district` | text | 行政區 |
| `basin` | text | 流域 |
| `river` | text | 河川 |
| `site_id` | text | 測站 ID（環境部全國唯一） |
| `site_name` | text | 測站名稱 |
| `site_name_en` | text | 英文名稱（可空） |
| `site_address` | text | 地址 |
| `status_of_use` | text | 啟用狀態 |
| `wq_std_grade` | text | 水體分類等級 |
| `longitude` | numeric | WGS84 經度（來自 `Gis_X`） |
| `latitude` | numeric | WGS84 緯度（來自 `Gis_Y`） |

| `risk_level` | text | `unpolluted`、`mild`、`moderate`、`severe` |

| `data_time` | timestamptz | ETL 寫入時間 |
| `wkb_geometry` | geometry(Point, 4326) | 測站位置（join 自測站基本表） |

### 河流漸層段表

建議資料表：`env_river_rpi_segments_latest`

| 欄位 | 型別 | 說明 |
|------|------|------|
| `segment_id` | text | `{river_id}-{upstream_site_id}-{downstream_site_id}`（PK） |
| `river_id` | text | MOENV `River_ID` |
| `river` | text | 河川中文名稱（沿用 MOENV） |
| `basin` | text | 流域 |
| `upstream_site_id` | text | 上游測站 ID |
| `upstream_site_name` | text | 上游測站名 |
| `upstream_city` | text | 上游測站所在城市 |
| `upstream_rpi` | numeric | 上游測站最新 RPI |
| `downstream_site_id` | text | 下游測站 ID |
| `downstream_site_name` | text | 下游測站名 |
| `downstream_city` | text | 下游測站所在城市 |
| `downstream_rpi` | numeric | 下游測站最新 RPI |
| `sample_month` | date | 來源月份 |
| `geometry_source` | text | `curated_route`（repo route asset）、`real_river`（沿 WRA 河道）或 `straight_line`（直線退場） |
| `data_time` | timestamptz | ETL 寫入時間 |
| `wkb_geometry` | geometry(LineString, 4326) | 河道折線段 |

漸層段建立流程：

1. ETL 啟動時讀取 `env_river_water_quality/assets/river_segment_routes.geojson`，以 `segment_id` 或 `{river_id}-{upstream_site_id}-{downstream_site_id}` 對應測站對；命中時直接使用該 route geometry 並標記 `geometry_source='curated_route'`。
2. 對 route asset 未涵蓋的測站對，下載並快取（7 天 TTL，預設 `/tmp/env_river_water_quality_cache/wra_cache/wra_river.zip`）水利署 `river.shp`。
3. 依 `RIVER_NAME_ALIAS = {"淡水河本流": "淡水河", "三峽河": "三峽溪"}` 將 MOENV 河川名映射到 WRA `NAME`。
4. 將每個測站投影到最近的 WRA LineString feature，取得 `t = line.project(point)`；測站配對仍以 MOENV `Station_Order` 排序。
5. 同特徵之相鄰測站使用 `shapely.ops.substring(line, t_a, t_b)` 切出實際河道段；跨特徵之測站對則由兩特徵之最近端點橋接（上游特徵 substring 至 endpoint → 下游特徵 substring 從 endpoint 至 t_b），標記 `geometry_source='real_river'`。
6. 任一測站投影距離 > 1500 公尺、找不到對應 WRA 河、或橋接無法構成有效折線時，該段退回直線連線並標記 `geometry_source='straight_line'`。

### ETL 規則

- 每次跑 ETL 都以 `(site_id)` 與 `(segment_id)` 為主鍵覆寫對應表。
- 不保留歷史月份。若未來需要趨勢圖，需另外新增定期快照表，但不在本版範圍。
- `MonthDate_Dec` 解析失敗或為空時 `sample_month` 設為 `NULL` 並標記 `rpi_flag='incomplete'`。
- 縣市過濾僅保留 `臺北市`、`新北市`。
- WRA shapefile 下載失敗會中斷 ETL（保留先前資料）；7 天 TTL 內會直接讀取快取，不重複下載。

### 資料更新與 metadata

- 排程：每日一次（MOENV 上游月更，但每日 poll 用以及時偵測 `MonthDate_Dec` 變更；WRA shapefile 不定期更新，本組件以本地快取與 7 天 TTL 處理）。
- 冪等鍵：`site_id`、`segment_id`。
- ETL 失敗時保留前一版本資料，並在 `dataset_info` 記錄 `last_success_time` 與 `last_attempt_time`。
- `dataset_info` 中 `env_river_monitoring_sites` 與 `env_river_site_rpi_latest` 的 geometry 類型為 `Point`、`env_river_rpi_segments_latest` 為 `LineString`，座標系統皆為 `EPSG:4326`。

## AI Chat 的結合方法

AI Chat 透過後端 tool calling 整合本組件，不直接讓前端呼叫資料庫。受限於資料來源僅有最新月份且無子指標，建議僅提供以下三個 tools：

| Tool | 參數 | 回傳 | 用途 |
|------|------|------|------|
| `get_river_rpi_summary` | `city_scope` | 最新月份各風險等級測站數、最高 RPI 測站、資料時間 | 回答整體水質風險概況 |
| `get_river_site_detail` | `site_id` | 測站基本資料、最新 RPI、風險等級、水體分類等級 | 供地圖點擊或單站詢問 |
| `set_river_water_view` | `city_scope`, `focus_river`, `focus_site_id` | 前端視圖控制指令 | 讓 AI 協助切換臺北/雙北、聚焦河川或測站 |

Tool 參數規則：

- `city_scope` 只允許 `taipei` 或 `twin_city`。
- `site_id` 必須是 `env_river_monitoring_sites.site_id`（環境部全國唯一）。
- 不提供 `focus_month`，因資料只有單月。

AI 回答需附帶資料時間與資料來源（固定為「環境部水質監測 GIS」），並在資料缺漏時明確說明限制。例如：當使用者詢問四項子指標數值、歷史趨勢或其他測項超標情況時，AI 應明確回覆此版本資料來源不提供該資訊；當測站 `risk_level='incomplete'` 時，AI 應指出該測站目前無檢測資料而不參與分布統計。
