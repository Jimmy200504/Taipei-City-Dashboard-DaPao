# 河川水質風險追蹤：雙北 RPI 測站地圖

## 資料

### 資料來源

本組件以「河川污染指數 RPI」追蹤雙北河川水質風險，並在地圖上以漸層折線呈現相鄰測站之間沿河道的污染程度變化。排程 DAG 抓取兩個 MOENV 端點作為測站資料來源：(1) 官方 `Get_point_WQStation_River` 提供環境部測站與已計算好的 `WQ_Index`；(2) `Get_point_WQStation_Ext_River` 提供其他單位（地方環保局等）測站與 DO/BOD5/SS/NH3-N 四項原始指標，由 ETL 重新計算 RPI。河川中心線幾何另由 repo 內人工檢核的 route asset 與水利署 shapefile 提供。

| 來源 | URL | 格式 | 用途 |
|------|-----|------|------|
| 環境部水質監測 GIS（官方測站） | `https://wq.moenv.gov.tw/EWQP_GIS/dataFile/AJAX_Main.aspx?Type=Get_point_WQStation_River` | JSON（AJAX 回傳） | 環境部官方測站基本資料、最新月份 `WQ_Index`、風險分級（直接取用，不重算） |
| 環境部水質監測 GIS（其他單位測站） | `https://wq.moenv.gov.tw/EWQP_GIS/dataFile/AJAX_Main.aspx?Type=Get_point_WQStation_Ext_River` | JSON（AJAX 回傳） | 地方環保局等其他單位測站基本資料、DO/BOD5/SS/NH3-N/導電度原始指標；本平台依四項指標分數平均重新計算 RPI |
| 環境部 站點詳細頁面（其他單位測站 DO 備援） | `https://wq.moenv.gov.tw/EWQP/zh/EnvWaterMonitoring/RiverWaterQuality.aspx?Func=FromGIS&Qry={SiteID}&Parent1={SiteMgt_ID}` | HTML | 當 Ext 端點 `Id_204`（DO）缺值時補回，依電極法優先、滴定法備援解析資料卡 |
| repo curated river routes（derived from OpenStreetMap waterway centerlines） | `env_river_water_quality/assets/river_segment_routes.geojson` | GeoJSON LineString | 主要河川測站對的人工檢核 route 幾何，供 ETL 優先套用 |
| 經濟部水利署 河川河道（河川支流線） | `https://gic.wra.gov.tw/gis/gic/API/Google/DownLoad.aspx?fname=RIVER&filetype=SHP` | ZIP / ESRI Shapefile（`river.shp`，53,497 條 LineString） | route asset 未涵蓋時的備援河川中心線幾何 |

上述來源皆為公開資料，**不需** API key。Route asset 由 OpenStreetMap waterway centerline 擷取後人工檢核，授權依 ODbL；WRA shapefile 採 TWD97 / EPSG:3826，ETL 內重投影至 EPSG:4326；data-built 年份為 2000，對於雙北主要河川仍作為備援來源。WRA 授權：政府資料開放授權條款-第 1 版。

Route asset 的重建是維護作業，不是排程 DAG 的一部分。若環境部新增或調整測站順序，可在 Airflow container 內產生候選檔：

```bash
PYTHONPATH=/opt/airflow/dags python \
  /opt/airflow/dags/proj_city_dashboard/env_river_water_quality/generate_river_segment_routes.py \
  --output /tmp/river_segment_routes.candidate.geojson \
  --report /tmp/river_segment_routes.report.json
```

工具預設同時涵蓋官方與其他單位（Ext_River）測站：

- **官方測站**：依上游 `River_ID + Station_Order` 排序。
- **其他單位測站**：以 `basin` 名稱對應到 **WRA** 河道（`NAME` 欄位）做投影排序，合成 `river_id="ext-river:{basin}"` 與 `station_order`（與 runtime 採同樣排序，確保 `segment_id` 一致），再走 OSM 最短路徑邏輯產生路線幾何。
- 若需強制官方-only 模式，加上 `--no-ext`。

工具會向 Overpass 查詢 OpenStreetMap `waterway=river|stream|canal` 線段，再以最短連通水線產生 candidate GeoJSON。`report` 會列出無法自動配對或測站離水線超過門檻的 segment，需人工檢查後才覆寫 committed asset。

WRA 河川名稱與 MOENV `River_Name` 多數一致；少數別名於 ETL 內以對照表處理：

| MOENV `River_Name` | WRA `NAME` |
|--------------------|------------|
| 淡水河本流 | 淡水河 |
| 三峽河 | 三峽溪 |

|-----------------------|--------------|--------------------|------|

#### `rpi_flag` 規則

| `rpi_flag` | 規則 |
|------------|------|
| `complete` | 官方來源：`WQ_Index` 為有效數值；其他單位來源：DO/BOD5/SS/NH3-N 四項皆有有效數值 |
| `incomplete` | 不滿足以上條件；不入圖表分母、不產生河段、不匯出到前端地圖 GeoJSON，但仍保留於 `env_river_monitoring_sites` 與 `env_river_site_rpi_latest` 兩張資料表中作為清單參考 |

## 前端

### 前端儀表板

前端儀表板支援 `臺北市` 與 `雙北` 城市範圍切換。backend `query_charts.city` 實際使用 `taipei` 與 `metrotaipei` 兩個值；切換城市範圍時，圖表依該 city 取對應 SQL 與 map config。

| 圖表 | query type | chart type | 顯示欄位 | 說明 |
|------|------------|------------|----------|------|
| 高風險測站排名 | `two_d` | `BarChart` | `x=site_name`, `y=rpi_value` | 最新月份 RPI 由高至低，預設 Top 10；包含官方與其他單位測站 |
| 風險等級分布 | `two_d` | `DonutChart` | `x=risk_level`, `y=site_count` | 最新月份各風險等級的測站數（單月快照，非時間序列）；包含官方與其他單位測站 |

兩張圖以 `rpi_flag = 'complete'` 篩選，`source_wq_index` 與 `calculated_from_items` 兩種來源同時納入分母。風險等級 series 來自 SQL `GROUP BY risk_level, risk_level_order` 的實際結果；目前 backend sample SQL 不補 0 值分類。`incomplete` 不入分母。

### 前端地圖圖層

前端地圖以「測站點 + 河流漸層線」呈現 RPI 空間分布：

- **測站點圖層**：合併兩種來源，僅匯出連到可見河段的官方與其他單位測站；無可見河段的孤立測站不顯示。顏色由 `component_maps.paint` 依 `risk_level` 對應：`unpolluted #67baca`、`mild #f8cf58`、`moderate #f5ad4a`、`severe #ed6a45`，fallback 為灰色。
- **河流漸層線圖層**：以兩種來源建立。**官方測站**直接使用上游提供的 `River_ID` + `Station_Order`；**其他單位測站**先把 `basin` 名稱對應到 WRA 河道，再依測站投影位置合成 `river_id="ext-river:{basin}"` 與 `station_order`。建立順序：
  - 優先使用 repo 內維護的測站對 route GeoJSON，將相鄰測站對對應到人工檢核過的河道折線，並標記 `geometry_source='curated_route'`。
  - 未涵蓋時退回 WRA 河川支流線投影：同特徵之相鄰測站使用 `shapely.ops.substring` 切出實際河道段，跨特徵時以兩特徵最近端點橋接，標記 `geometry_source='real_river'`。
  - 任一測站投影距離超過 1500 m、找不到對應 WRA 河川、或橋接失敗時，最後退回 `geometry_source='straight_line'`。
  - 沿線以 `upstream_rpi` → `downstream_rpi` 線性內插上色（兩種來源的 RPI 在地圖上以同一個漸層展示）。

河流線段在 frontend `mapStore.js` 另有專用處理：`env_river_segments_*` 的原始 GeoJSON 會先被切成多個短 `LineString` piece，每個 piece 依線上進度把 `upstream_rpi` 與 `downstream_rpi` 內插成 `rpi_value`，再由 Mapbox paint 以 `rpi_value` 做連續色階。這會覆蓋 backend sample SQL 中較簡單的平均 RPI line paint。

切換為 `臺北市` 時僅顯示臺北市測站、且兩端皆位於臺北市的河段；切換為 `雙北` 時同時顯示雙北測站與所有河段（包含跨市段）。Data-end 匯出 GeoJSON 時會先移除端點無法貼近測站的線段，測站點則只匯出該城市範圍內可連到可見河段的端點；其他單位測站若沒有可見河段，不以孤立點呈現。地圖座標系統為 WGS84/EPSG:4326。

地圖 popup 顯示欄位由 `component_maps.property` 控制。測站點圖層目前顯示：

- 測站名稱：`site_name`
- RPI 值與風險等級：`rpi_value`、`risk_level`
- RPI 計算方式：`rpi_method`（`source_wq_index` 或 `calculated_from_items`）
- 採樣月份：`sample_month`
- 行政區：`district`（其他單位測站為空）
- 河川：`river`
- 水體分類等級：`wq_std_grade`（其他單位測站為空）
- 資料來源：`source_label`（`moenv_river` 或 `moenv_ext_river`）
- 子指標：`do_value`、`bod5_value`、`ss_value`、`nh3n_value`、`conductivity_value`（僅其他單位測站有值；官方測站留空）
- DO 量測方法：`do_method`（其他單位測站專用；指出 DO 是來自 Ext 端點本身或站點詳細頁面 電極法／滴定法）

河段線圖層目前顯示：

- 上游測站與 RPI：`upstream_site_name`、`upstream_rpi`
- 下游測站與 RPI：`downstream_site_name`、`downstream_rpi`
- 幾何來源：`geometry_source`
- 採樣月份：`sample_month`

若測站缺座標（`Gis_X` 或 `Gis_Y` 為空），該測站不進入地圖圖層。

## 後端

後端資料庫設定由 `Taipei-City-Dashboard-BE/db-sample-data/env_river_water_quality.sql` 建立。它新增兩個 component、兩個 chart config、四個 local GeoJSON map config，並為 `taipei` 與 `metrotaipei` 各寫入一組 `query_charts`。後端執行的是兩種圖表 SQL；地圖圖層不是 backend SQL 查詢，而是透過 `component_maps` 回傳 `index/type/source/paint/property` 給 frontend，frontend 再依 `index` 讀取 `/mapData/{index}.geojson`。

### 高風險測站排名

```sql
SELECT site_name AS x_axis, rpi_value AS data
FROM env_river_site_rpi_latest
WHERE
  -- taipei query
  city = '臺北市'
  AND rpi_flag = 'complete'
ORDER BY rpi_value DESC
LIMIT 10;
```

`metrotaipei` 版本將條件改為 `city IN ('臺北市','新北市')`。

### 風險等級分布

```sql
SELECT risk_level AS x_axis, COUNT(*)::int AS data
FROM env_river_site_rpi_latest
WHERE
  -- taipei query
  city = '臺北市'
  AND rpi_flag = 'complete'
GROUP BY risk_level, risk_level_order
ORDER BY risk_level_order;
```

`metrotaipei` 版本將條件改為 `city IN ('臺北市','新北市')`。

### 地圖設定

`component_maps` 會建立四個 local GeoJSON layer：

| index | title | type | source |
|-------|-------|------|--------|
| `env_river_sites_taipei` | 臺北市河川測站 | `circle` | `geojson` |
| `env_river_sites_metrotaipei` | 雙北河川測站 | `circle` | `geojson` |
| `env_river_segments_taipei` | 臺北市河川 RPI 漸層段 | `line` | `geojson` |
| `env_river_segments_metrotaipei` | 雙北河川 RPI 漸層段 | `line` | `geojson` |

`query_charts.map_config_ids` 將 `taipei` chart 綁到臺北市點與線，將 `metrotaipei` chart 綁到雙北點與線。map config 的 `property` 定義 popup 顯示欄位；真正的 GeoJSON 內容由 data-end 匯出到 frontend `public/mapData`。

## 資料端邏輯

ETL 從兩個 MOENV AJAX 端點抓取 JSON：(1) 官方 `Get_point_WQStation_River` 以 `County_Name IN ('臺北市', '新北市')` 篩選；(2) 其他單位 `Get_point_WQStation_Ext_River` 以 `New_County_Cname IN ('臺北市', '新北市')` 篩選。兩源各自標準化後，依 `site_id`（含 `ext:` 前綴避免碰撞）合併為共用的 sites/latest DataFrame；下載並快取（7 天 TTL）水利署 `river.shp` 作備援；讀取 repo route asset 作主要河道幾何；最後寫入三張表並匯出四個 frontend local GeoJSON。河段建立同時納入官方測站與其他單位測站：官方來源使用 `River_ID` / `Station_Order`，其他單位來源在 segment builder 內合成 `river_id` / `station_order`。DAG 對三張 ready table 採 replace 行為，實作上以 transaction 先 `TRUNCATE` 再 append。

| `risk_level_order` | integer | 圖表排序鍵（1~4） |

| `do_value` | numeric | DO mg/L（僅其他單位來源） |
| `bod5_value` | numeric | BOD5 mg/L（僅其他單位來源） |
| `ss_value` | numeric | SS mg/L（僅其他單位來源） |
| `nh3n_value` | numeric | NH3-N mg/L（僅其他單位來源） |
| `conductivity_value` | numeric | 導電度 μS/cm（僅其他單位來源；不入 RPI） |
| `do_score` | numeric | DO 子指標分數（1/3/6/10） |

| `ss_score` | numeric | SS 子指標分數 |

### 河流漸層段表

建議資料表：`env_river_rpi_segments_latest`

| 欄位 | 型別 | 說明 |
|------|------|------|
| `segment_id` | text | `{river_id}-{upstream_site_id}-{downstream_site_id}`（PK） |
| `river_id` | text | MOENV `River_ID` |
| `river` | text | 河川中文名稱（沿用 MOENV） |
| `basin` | text | 流域 |
| `upstream_site_id` | text | 上游測站 ID |
| `upstream_site_name` | text | 上游測站名 |
| `upstream_city` | text | 上游測站所在城市 |
| `upstream_rpi` | numeric | 上游測站最新 RPI |
| `downstream_site_id` | text | 下游測站 ID |
| `downstream_site_name` | text | 下游測站名 |
| `downstream_city` | text | 下游測站所在城市 |
| `downstream_rpi` | numeric | 下游測站最新 RPI |
| `sample_month` | date | 來源月份 |
| `geometry_source` | text | `curated_route`（repo route asset）、`real_river`（沿 WRA 河道）或 `straight_line`（直線退場） |
| `data_time` | timestamptz | ETL 寫入時間 |
| `wkb_geometry` | geometry(LineString, 4326) | 河道折線段 |

漸層段建立流程：

1. ETL 啟動時讀取 `env_river_water_quality/assets/river_segment_routes.geojson`，以 `segment_id` 或 `{river_id}-{upstream_site_id}-{downstream_site_id}` 對應測站對；命中時直接使用該 route geometry 並標記 `geometry_source='curated_route'`。
2. route asset 與 WRA 幾何的端點若在 750 m 內可貼近測站，ETL 會把線段端點吸附到測站座標。
3. 對 route asset 未涵蓋的測站對，下載並快取（7 天 TTL，預設 `/tmp/env_river_water_quality_cache/wra_cache/wra_river.zip`）水利署 `river.shp`。
4. 依 `RIVER_NAME_ALIAS = {"淡水河本流": "淡水河", "三峽河": "三峽溪"}` 將 MOENV 河川名映射到 WRA `NAME`。
5. **其他單位測站排序**：在進入步驟 6 之前，對 `source_label='moenv_ext_river'` 的測站做排序。若 `basin` 名稱可對應 WRA `NAME`，將該 basin 內所有 Ext 測站投影到匹配的 LineString，依 `(feature_idx, t_along)` 排序產生合成 `station_order`，並設 `river_id="ext-river:{basin}"`。若 basin 無 WRA 對應但有兩座以上完整測站，依測站座標主軸排序並同樣合成 `river_id` / `station_order`，後續以 `straight_line` 產生連線。投影距離 > 1500 m 的 Ext 測站維持無 `river_id`，不參與河段。
6. 將每個測站投影到最近的 WRA LineString feature，取得 `t = line.project(point)`；官方測站配對以 MOENV `Station_Order` 排序，Ext 測站以步驟 5 的合成 `station_order` 排序。
7. 同特徵之相鄰測站使用 `shapely.ops.substring(line, t_a, t_b)` 切出實際河道段；跨特徵之測站對則由兩特徵之最近端點橋接（上游特徵 substring 至 endpoint → 下游特徵 substring 從 endpoint 至 t_b），標記 `geometry_source='real_river'`。
8. 任一測站投影距離 > 1500 公尺、找不到對應 WRA 河、或橋接無法構成有效折線時，該段退回直線連線並標記 `geometry_source='straight_line'`。
9. 匯出 frontend GeoJSON 前，ETL 只保留兩端都在 75 m 內連到測站點的線段；測站點只匯出可連到可見河段的端點，Ext 測站無對應河段時不以孤立點呈現。

### ETL 規則

- 每次跑 ETL 都覆寫 `env_river_monitoring_sites`、`env_river_site_rpi_latest`、`env_river_rpi_segments_latest` 三張表。
- 不保留歷史月份。若未來需要趨勢圖，需另外新增定期快照表，但不在本版範圍。
- `MonthDate_Dec` 解析失敗或為空時 `sample_month` 設為 `NULL` 並標記 `rpi_flag='incomplete'`。
- 縣市過濾僅保留 `臺北市`、`新北市`（官方來源 `County_Name`、其他單位來源 `New_County_Cname`）。
- 其他單位來源指標解析：`<X` 視為 `0`、`－` / 空字串 / `null` / NaN 視為缺值；任一指標缺值即標記 `rpi_flag='incomplete'` 且不寫入 `rpi_value`。
- 其他單位來源 `Coord_Type` 必須為 `WGS84`，其他值（如 `TWD97`）會被 ETL 略過並記 warning。
- DO 補值策略：當其他單位測站 `Id_204` 缺值，但其餘三項指標至少有一項可用時，ETL 會以該測站 `(SiteID, SiteMgt_ID)` 呼叫 MOENV 站點詳細頁面，從 `<dl class="dataCardWrap">` 抽 `溶氧(電極法)`，缺則用 `溶氧(滴定法)`，並把實際使用的方法寫入 `do_method`。詳細頁面預設顯示為其最新月份；ETL 會檢查頁面下拉選單的年/月與 `sample_month` 一致才採用，避免引入舊月資料。HTTP 失敗或頁面無資料時不會中斷 DAG，僅記 warning，該站維持 `rpi_flag='incomplete'`。本機驗證實際效果：雙北其他單位測站 RPI 完整度由 28/94 提升到 73/94（45 站額外從 滴定法 補回，當期環境下並未取得電極法 DO）。
- WRA shapefile 下載失敗會中斷 ETL；7 天 TTL 內會直接讀取快取，不重複下載。

### 資料更新與 metadata

- 排程：`0 4 * * *`，每日臺北時間 04:00 執行；MOENV 上游月更，但每日 poll 用以及時偵測 `MonthDate_Dec` 變更；WRA shapefile 不定期更新，本組件以本地快取與 7 天 TTL 處理。
- 冪等鍵：`site_id`、`segment_id`。
- DAG 成功後以 `update_lasttime_in_data_to_dataset_info` 將 `lasttime_in_data` 更新為最新 `sample_month`，若來源月份皆無法解析則使用 ETL 執行時間。
- `job_config.json` 中 `gis_format` 為 `Point,LineString`，座標系統皆為 `EPSG:4326`。

## AI Chat 的結合

目前專案內尚未實作河川水質專用 AI tool；以下是後續接入建議。AI Chat 可透過後端 tool calling 整合本組件，不直接讓前端呼叫資料庫。受限於資料來源僅有最新月份，建議提供以下三個 tools：

| Tool | 參數 | 回傳 | 用途 |
|------|------|------|------|
| `get_river_rpi_summary` | `city_scope` | 最新月份各風險等級測站數、最高 RPI 測站、資料時間、官方/其他單位來源各別計數 | 回答整體水質風險概況 |
| `get_river_site_detail` | `site_id` | 測站基本資料、最新 RPI、風險等級、`rpi_method`；其他單位測站額外回傳 DO/BOD5/SS/NH3-N/導電度與各項分數 | 供地圖點擊或單站詢問 |
| `set_river_water_view` | `city_scope`, `focus_river`, `focus_site_id` | 前端視圖控制指令 | 讓 AI 協助切換臺北/雙北、聚焦河川或測站 |

Tool 參數規則：

- `city_scope` 只允許 `taipei` 或 `metrotaipei`。
- `site_id` 須符合 `env_river_monitoring_sites.site_id`：官方測站為環境部 `Station_ID`；其他單位測站為 `ext:{SiteMgt_ID}:{SiteID}`。
- 不提供 `focus_month`，因資料只有單月。

AI 回答需附帶資料時間與資料來源，並在資料缺漏時明確說明限制：

- 官方測站 popup 詢問 DO/BOD5/SS/NH3-N 數值時，AI 應指出官方端點僅回傳整體 `WQ_Index`，子指標僅其他單位測站可查。
- 其他單位測站若 `rpi_flag='incomplete'`（例如 DO 為 `－`），AI 應指出該測站某項指標缺值，因此本月不入分布統計。
- 比較兩種來源的 RPI 時，AI 應提醒 `source_wq_index` 與 `calculated_from_items` 計算口徑不同，數值嚴格意義不直接可比。
- 任何情況下都不提供歷史趨勢或其他測項（pH、總磷、重金屬等）之回答。
