# 河川水質風險追蹤：雙北 RPI 測站地圖

## 資料

### 資料來源

本組件以「河川污染指數 RPI」追蹤雙北河川水質風險，並在地圖上以漸層折線呈現相鄰測站之間沿河道的污染程度變化。排程 DAG 直接抓取兩個公開來源：環境部負責測站與 WQ_Index，水利署負責備援河川中心線幾何；repo 內另維護一份由 OpenStreetMap waterway centerline 產生並人工檢核的 route asset，供 ETL 優先使用。

| 來源 | URL | 格式 | 用途 |
|------|-----|------|------|
| 環境部水質監測 GIS | `https://wq.moenv.gov.tw/EWQP_GIS/dataFile/AJAX_Main.aspx?Type=Get_point_WQStation_River` | JSON（AJAX 回傳） | 全國河川測站基本資料、最新月份 WQ_Index、風險分級 |
| repo curated river routes（derived from OpenStreetMap waterway centerlines） | `env_river_water_quality/assets/river_segment_routes.geojson` | GeoJSON LineString | 主要河川測站對的人工檢核 route 幾何，供 ETL 優先套用 |
| 經濟部水利署 河川河道（河川支流線） | `https://gic.wra.gov.tw/gis/gic/API/Google/DownLoad.aspx?fname=RIVER&filetype=SHP` | ZIP / ESRI Shapefile（`river.shp`，53,497 條 LineString） | route asset 未涵蓋時的備援河川中心線幾何 |

上述來源皆為公開資料，**不需** API key。Route asset 由 OpenStreetMap waterway centerline 擷取後人工檢核，授權依 ODbL；WRA shapefile 採 TWD97 / EPSG:3826，ETL 內重投影至 EPSG:4326；data-built 年份為 2000，對於雙北主要河川仍作為備援來源。WRA 授權：政府資料開放授權條款-第 1 版。

Route asset 的重建是維護作業，不是排程 DAG 的一部分。若環境部新增或調整測站順序，可在 Airflow container 內產生候選檔：

```bash
PYTHONPATH=/opt/airflow/dags python \
  /opt/airflow/dags/proj_city_dashboard/env_river_water_quality/generate_river_segment_routes.py \
  --output /tmp/river_segment_routes.candidate.geojson \
  --report /tmp/river_segment_routes.report.json
```

工具會重新抓取 MOENV 測站、向 Overpass 查詢 OpenStreetMap `waterway=river|stream|canal` 線段，依 `river_id + station_order` 建立相鄰測站對，並以最短連通水線產生 candidate GeoJSON。`report` 會列出無法自動配對或測站離水線超過門檻的 segment，需人工檢查後才覆寫 committed asset。

WRA 河川名稱與 MOENV `River_Name` 多數一致；少數別名於 ETL 內以對照表處理：

| MOENV `River_Name` | WRA `NAME` |
|--------------------|------------|
| 淡水河本流 | 淡水河 |
| 三峽河 | 三峽溪 |

### 資料缺漏（Lacked Data）

此端點僅回傳每個測站「最新一個月」的整體 WQ_Index 與分級結果，不含子指標數值與其他測項。下列項目本端點不提供，因此本組件**不**呈現對應功能：

1. **歷史月份**：僅有 `MonthDate_Dec` 一個月份欄位，無法繪製多月趨勢或月份比例長條圖。
2. **四項子指標數值**：DO、BOD5、SS、NH3-N 的原始 mg/L 值與各自分數均不提供，無法在 tooltip 顯示子指標、亦無法重算 RPI。
3. **其他測項**：pH、導電度、大腸桿菌群、濁度、總磷、重金屬等均不提供，「異常測項分布」圖無法建立。
4. **採樣日期與時刻**：僅有年月（例 `2026 年 3 月`），無採樣日期與 `HH:MM`。
5. **品質註記**：無 `<MDL`、`@LOQ`、`-` 等檢測極限標註。
6. **河川中心線幾何**：MOENV 端點僅含測站點位。ETL 目前優先使用 repo 內 `river_segment_routes.geojson` 的人工檢核 route；asset 未涵蓋時才用 WRA `river.shp` 投影與切段；仍失敗時退回直線連線（`geometry_source='straight_line'`）。WRA `river.shp` 為 2000 年圖資且為碎片化資料，僅作備援，不再是主要地圖幾何來源。
7. **主要異常測項**：需由各測項超標判定，本端點無此資訊。

### RPI 與風險分級

`rpi_value` 直接取自 `WQ_Index`，**不**重新以四項子指標計算。`risk_level` 由 `WQ_Index_Dec` 對應：

| `WQ_Index_Dec`（原文） | `risk_level` | `risk_level_order` | 說明 |
|-----------------------|--------------|--------------------|------|
| 未（稍）受污染 | `unpolluted` | 1 | 入圖表分母、地圖以對應顏色顯示 |
| 輕度污染 | `mild` | 2 | 同上 |
| 中度污染 | `moderate` | 3 | 同上 |
| 嚴重污染 | `severe` | 4 | 同上 |
| 無檢測資料 | `NULL` | — | `rpi_flag='incomplete'`，不入圖表分母；目前也不產生河段 |

`rpi_flag` 僅有兩種值：

| `rpi_flag` | 規則 |
|------------|------|
| `complete` | `WQ_Index` 為有效數值 |
| `incomplete` | `WQ_Index_Dec = 無檢測資料` 或 `WQ_Index` 缺值 |

## 前端

### 前端儀表板

前端儀表板支援 `臺北市` 與 `雙北` 城市範圍切換。backend `query_charts.city` 實際使用 `taipei` 與 `metrotaipei` 兩個值；切換城市範圍時，圖表依該 city 取對應 SQL 與 map config。

| 圖表 | query type | chart type | 顯示欄位 | 說明 |
|------|------------|------------|----------|------|
| 高風險測站排名 | `two_d` | `BarChart` | `x=site_name`, `y=rpi_value` | 最新月份 RPI 由高至低，預設 Top 10 |
| 風險等級分布 | `two_d` | `DonutChart` | `x=risk_level`, `y=site_count` | 最新月份各風險等級的測站數（單月快照，非時間序列） |

風險等級 series 來自 SQL `GROUP BY risk_level, risk_level_order` 的實際結果；目前 backend sample SQL 不補 0 值分類。`incomplete` 不入分母。

### 前端地圖圖層

前端地圖以「測站點 + 河流漸層線」呈現 RPI 空間分布：

- **測站點圖層**：每個可見河段端點測站為一個點，顏色由 `component_maps.paint` 依 `risk_level` 對應：`unpolluted #67baca`、`mild #f8cf58`、`moderate #f5ad4a`、`severe #ed6a45`，fallback 為灰色。因河段建立會排除缺 RPI 的測站，實際輸出的 mapData 點位通常只包含可連到可見河段的完整資料測站。
- **河流漸層線圖層**：ETL 優先使用 repo 內維護的測站對河道 route GeoJSON，將相鄰測站對對應到人工檢核過的河道折線，並標記 `geometry_source='curated_route'`。若 route asset 未涵蓋該測站對，才退回 WRA 河川支流線投影：同特徵之相鄰測站使用 `shapely.ops.substring` 切出實際河道段，跨特徵時以兩特徵最近端點橋接，標記 `geometry_source='real_river'`。任一測站投影距離超過 1500 m、找不到對應 WRA 河川、或橋接失敗時，最後退回 `geometry_source='straight_line'`。沿線以 `upstream_rpi` → `downstream_rpi` 線性內插上色。

河流線段在 frontend `mapStore.js` 另有專用處理：`env_river_segments_*` 的原始 GeoJSON 會先被切成多個短 `LineString` piece，每個 piece 依線上進度把 `upstream_rpi` 與 `downstream_rpi` 內插成 `rpi_value`，再由 Mapbox paint 以 `rpi_value` 做連續色階。這會覆蓋 backend sample SQL 中較簡單的平均 RPI line paint。

切換為 `臺北市` 時僅顯示臺北市測站、且兩端皆位於臺北市的河段；切換為 `雙北` 時同時顯示雙北測站與所有河段（包含跨市段）。Data-end 匯出 GeoJSON 時會先移除端點無法貼近測站的線段，再只匯出該城市範圍內可見河段的端點，避免顯示沒有對應河段的孤立測站點。地圖座標系統為 WGS84/EPSG:4326。

地圖 popup 顯示欄位由 `component_maps.property` 控制。測站點圖層目前顯示：

- 測站名稱：`site_name`
- RPI 值與風險等級：`rpi_value`、`risk_level`
- 採樣月份：`sample_month`
- 行政區：`district`
- 河川：`river`
- 水體分類等級：`wq_std_grade`

河段線圖層目前顯示：

- 上游測站與 RPI：`upstream_site_name`、`upstream_rpi`
- 下游測站與 RPI：`downstream_site_name`、`downstream_rpi`
- 幾何來源：`geometry_source`
- 採樣月份：`sample_month`

若測站缺座標（`Gis_X` 或 `Gis_Y` 為空），該測站不進入地圖圖層。

## 後端

後端資料庫設定由 `Taipei-City-Dashboard-BE/db-sample-data/env_river_water_quality.sql` 建立。它新增兩個 component、兩個 chart config、四個 local GeoJSON map config，並為 `taipei` 與 `metrotaipei` 各寫入一組 `query_charts`。後端執行的是兩種圖表 SQL；地圖圖層不是 backend SQL 查詢，而是透過 `component_maps` 回傳 `index/type/source/paint/property` 給 frontend，frontend 再依 `index` 讀取 `/mapData/{index}.geojson`。

### 高風險測站排名

```sql
SELECT site_name AS x_axis, rpi_value AS data
FROM env_river_site_rpi_latest
WHERE
  -- taipei query
  city = '臺北市'
  AND rpi_flag = 'complete'
ORDER BY rpi_value DESC
LIMIT 10;
```

`metrotaipei` 版本將條件改為 `city IN ('臺北市','新北市')`。

### 風險等級分布

```sql
SELECT risk_level AS x_axis, COUNT(*)::int AS data
FROM env_river_site_rpi_latest
WHERE
  -- taipei query
  city = '臺北市'
  AND rpi_flag = 'complete'
GROUP BY risk_level, risk_level_order
ORDER BY risk_level_order;
```

`metrotaipei` 版本將條件改為 `city IN ('臺北市','新北市')`。

### 地圖設定

`component_maps` 會建立四個 local GeoJSON layer：

| index | title | type | source |
|-------|-------|------|--------|
| `env_river_sites_taipei` | 臺北市河川測站 | `circle` | `geojson` |
| `env_river_sites_metrotaipei` | 雙北河川測站 | `circle` | `geojson` |
| `env_river_segments_taipei` | 臺北市河川 RPI 漸層段 | `line` | `geojson` |
| `env_river_segments_metrotaipei` | 雙北河川 RPI 漸層段 | `line` | `geojson` |

`query_charts.map_config_ids` 將 `taipei` chart 綁到臺北市點與線，將 `metrotaipei` chart 綁到雙北點與線。map config 的 `property` 定義 popup 顯示欄位；真正的 GeoJSON 內容由 data-end 匯出到 frontend `public/mapData`。

| `data_time` | timestamptz | ETL 寫入時間 |
| `wkb_geometry` | geometry(LineString, 4326) | 河道折線段 |

漸層段建立流程：

1. ETL 啟動時讀取 `env_river_water_quality/assets/river_segment_routes.geojson`，以 `segment_id` 或 `{river_id}-{upstream_site_id}-{downstream_site_id}` 對應測站對；命中時直接使用該 route geometry 並標記 `geometry_source='curated_route'`。
2. route asset 與 WRA 幾何的端點若在 750 m 內可貼近測站，ETL 會把線段端點吸附到測站座標。
3. 對 route asset 未涵蓋的測站對，下載並快取（7 天 TTL，預設 `/tmp/env_river_water_quality_cache/wra_cache/wra_river.zip`）水利署 `river.shp`。
4. 依 `RIVER_NAME_ALIAS = {"淡水河本流": "淡水河", "三峽河": "三峽溪"}` 將 MOENV 河川名映射到 WRA `NAME`。
5. 將每個測站投影到最近的 WRA LineString feature，取得 `t = line.project(point)`；測站配對仍以 MOENV `Station_Order` 排序。
6. 同特徵之相鄰測站使用 `shapely.ops.substring(line, t_a, t_b)` 切出實際河道段；跨特徵之測站對則由兩特徵之最近端點橋接（上游特徵 substring 至 endpoint → 下游特徵 substring 從 endpoint 至 t_b），標記 `geometry_source='real_river'`。
7. 任一測站投影距離 > 1500 公尺、找不到對應 WRA 河、或橋接無法構成有效折線時，該段退回直線連線並標記 `geometry_source='straight_line'`。
8. 匯出 frontend GeoJSON 前，ETL 只保留兩端都在 75 m 內連到測站點的線段，並只匯出這些可見線段的端點測站。

### ETL 規則

- 每次跑 ETL 都覆寫 `env_river_monitoring_sites`、`env_river_site_rpi_latest`、`env_river_rpi_segments_latest` 三張表。
- 不保留歷史月份。若未來需要趨勢圖，需另外新增定期快照表，但不在本版範圍。
- `MonthDate_Dec` 解析失敗或為空時 `sample_month` 設為 `NULL` 並標記 `rpi_flag='incomplete'`。
- 縣市過濾僅保留 `臺北市`、`新北市`。
- WRA shapefile 下載失敗會中斷 ETL；7 天 TTL 內會直接讀取快取，不重複下載。

### 資料更新與 metadata

- 排程：`0 4 * * *`，每日臺北時間 04:00 執行；MOENV 上游月更，但每日 poll 用以及時偵測 `MonthDate_Dec` 變更；WRA shapefile 不定期更新，本組件以本地快取與 7 天 TTL 處理。
- 冪等鍵：`site_id`、`segment_id`。
- DAG 成功後以 `update_lasttime_in_data_to_dataset_info` 將 `lasttime_in_data` 更新為最新 `sample_month`，若來源月份皆無法解析則使用 ETL 執行時間。
- `job_config.json` 中 `gis_format` 為 `Point,LineString`，座標系統皆為 `EPSG:4326`。

## AI Chat 的結合方法（尚未實作）

目前專案內尚未實作河川水質專用 AI tool；以下是後續接入建議。AI Chat 可透過後端 tool calling 整合本組件，不直接讓前端呼叫資料庫。受限於資料來源僅有最新月份且無子指標，建議僅提供以下三個 tools：

| Tool | 參數 | 回傳 | 用途 |
|------|------|------|------|
| `get_river_rpi_summary` | `city_scope` | 最新月份各風險等級測站數、最高 RPI 測站、資料時間 | 回答整體水質風險概況 |
| `get_river_site_detail` | `site_id` | 測站基本資料、最新 RPI、風險等級、水體分類等級 | 供地圖點擊或單站詢問 |
| `set_river_water_view` | `city_scope`, `focus_river`, `focus_site_id` | 前端視圖控制指令 | 讓 AI 協助切換臺北/雙北、聚焦河川或測站 |

Tool 參數規則：

- `city_scope` 只允許 `taipei` 或 `metrotaipei`。
- `site_id` 必須是 `env_river_monitoring_sites.site_id`（環境部全國唯一）。
- 不提供 `focus_month`，因資料只有單月。

AI 回答需附帶資料時間與資料來源（固定為「環境部水質監測 GIS」），並在資料缺漏時明確說明限制。例如：當使用者詢問四項子指標數值、歷史趨勢或其他測項超標情況時，AI 應明確回覆此版本資料來源不提供該資訊；當測站 `rpi_flag='incomplete'` 時，AI 應指出該測站目前無檢測資料而不參與分布統計。
