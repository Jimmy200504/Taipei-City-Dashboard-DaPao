# 夜間城市能源效率：雙北路燈瓦數分布

## 資料

### 資料來源

本組件整合臺北市與新北市路燈點位與瓦數資料，用以呈現行政區平均耗電強度與各瓦數等級路燈分布。

| 來源 | 資料集名稱 | 提供單位 | 更新頻率 |
|------|-----------|---------|---------|
| 臺北市政府資料平台 | 臺北市路燈位置分布圖 | 臺北市工務局 | 不定期 |
| 新北市政府開放資料 | 新北市路燈資料 | 新北市工務局 | 每週 |

臺北市靜態檔案：
```text
https://tppkl.blob.core.windows.net/blobfs/TaipeiLight.json
https://tppkl.blob.core.windows.net/blobfs/TaipeiLight.csv
```

新北市分頁 API：
```text
https://data.ntpc.gov.tw/api/datasets/39149fe0-85ab-4e6c-99e5-60657d44895f/json?limit=1000&offset=0
```
新北市資料集共約 280,114 筆，需以 `limit` / `offset` 分頁抓取完整資料。

### 欄位解讀

#### 臺北市欄位

臺北市一筆記錄代表一根燈桿，燈桿上可同時裝設最多五種燈具（以 `LightKind1–5` 與 `LightWatt1–5` 表示）。`Quantity` 為該燈桿路燈總數量。座標為 TWD97 平面座標，ETL 須轉換為 WGS84。

| 欄位 | 說明 | 備註 |
|------|------|------|
| `SerialNumber` | 路燈編號 | 主鍵 |
| `Dist` | 行政區 | 如中正區、信義區 |
| `Quantity` | 燈桿燈數量 | 整數 |
| `LightKind1`–`LightKind5` | 燈種 1–5 | 如 LED、鈉燈、複金屬燈；第 2–5 欄位可為空 |
| `LightWatt1`–`LightWatt5` | 瓦數 1–5 | 對應燈種功率；需清理為數值 |
| `LightHeight` | 燈桿高度（公尺） | 數值 |
| `LightYear` | 使用年分（西元） | 整數 |
| `TWD97X` | TWD97 X 座標（東向） | 需轉 WGS84 |
| `TWD97Y` | TWD97 Y 座標（北向） | 需轉 WGS84 |
| `UpdDate` | 記錄更新日期 | 資料時間來源 |

#### 新北市欄位

新北市一筆記錄代表一盞路燈，已提供 WGS84 座標，但無燈種與裝設年分欄位。

| 欄位 | 說明 | 備註 |
|------|------|------|
| `seqno` | 路燈序號 | 主鍵，格式如 `390001` |
| `town` | 行政區 | 如八里區、板橋區 |
| `address` | 地址 | 部分記錄以 `*` 遮蔽 |
| `power` | 瓦數（字串） | 需清理為數值，單位 W |
| `x` | TWD97 X 座標 | 字串，可轉數值 |
| `y` | TWD97 Y 座標 | 字串，可轉數值 |
| `longitude` | WGS84 經度 | 字串，可轉數值；直接使用 |
| `latitude` | WGS84 緯度 | 字串，可轉數值；直接使用 |
| `height` | 燈桿高度 | 多為空值，保留 nullable |
| `countycode` | 縣市代碼 | 65000 代表新北市 |

#### 雙北欄位對照

| 概念 | 臺北欄位 | 新北欄位 |
|------|---------|---------|
| 路燈 ID | `SerialNumber` | `seqno` |
| 行政區 | `Dist` | `town` |
| 地址 | 無 | `address` |
| 瓦數 | `LightWatt1–5`（多燈種） | `power`（單一） |
| 燈種 | `LightKind1–5` | 無 |
| 燈桿高 | `LightHeight` | `height`（多空值） |
| 裝設年分 | `LightYear` | 無 |
| 每桿燈數 | `Quantity` | 隱含 1 |
| 座標 | TWD97 → 需轉換 | WGS84 直接使用 |

### 瓦數級距定義

ETL 依清理後 `watt` 數值劃分為以下固定級距，用於地圖顏色編碼與圓餅圖：

| `watt_bucket` | 規則 | 代表燈種 |
|---------------|------|---------|
| `ultra_low` | `watt <= 30` | 現代 LED |
| `low` | `31 <= watt <= 80` | 中功率 LED |
| `medium` | `81 <= watt <= 150` | 高功率 LED、舊型節能燈 |
| `high` | `151 <= watt <= 250` | 高壓鈉燈、複金屬燈 |
| `very_high` | `watt > 250` | 高功率傳統燈 |
| `unknown` | `power` 或 `watt` 無法解析 | 資料缺漏 |

## 前端

### 前端儀表板

前端儀表板支援 `臺北市` 與 `雙北` 城市範圍切換。切換城市範圍時，所有圖表依 `city_scope` 重新查詢。

| 圖表 | query type | chart type | 顯示欄位 | 說明 |
|------|------------|------------|----------|------|
| 行政區平均瓦數深淺圖 | `two_d` | `DistrictChart` | `x=district`, `y=avg_watt` | 行政區路燈平均耗電強度，數值越高顏色越深 |
| 全區瓦數級距比例 | `percent` | `DonutChart` | `x=watt_bucket`, `y=light_count` | 顯示各瓦數級距路燈數量占比 |

`DistrictChart` 需依 `avg_watt` 降序排列，讓高耗電行政區在圖表頂端顯示。

### 前端地圖圖層

地圖以每盞路燈作為點位，點的顏色依 `watt_bucket` 編碼：

| `watt_bucket` | 地圖顏色（建議） |
|---------------|----------------|
| `ultra_low` | 藍色（冷色系低值） |
| `low` | 青色 |
| `medium` | 黃色 |
| `high` | 橘色 |
| `very_high` | 紅色（高耗電警示） |
| `unknown` | 灰色 |

切換為 `臺北市` 時只顯示臺北市點位；切換為 `雙北` 時同時顯示臺北市與新北市點位。

地圖點擊路燈後，彈跳資訊顯示：

- 城市與行政區：`city`、`district`
- 地址：`address`（臺北市無地址欄位，顯示座標或行政區）
- 燈種：`light_type`（新北市無燈種資料時顯示「無資料」）
- 瓦數：`watt` W（附 `watt_bucket` 級距標籤）
- 燈桿高度：`pole_height` m（有資料時顯示）
- 裝設年分：`light_year`（臺北市有；新北市無）
- 資料時間：`data_time`
- 資料來源：臺北市政府 / 新北市政府

若 `longitude` / `latitude` 缺漏（或 TWD97 座標轉換失敗），該筆不得進入地圖圖層，但仍可保留於行政區統計。

## 後端

後端需提供前端儀表板與地圖圖層兩類資料：行政區聚合圖表資料與路燈點位資料。

### 行政區平均瓦數深淺圖

```sql
SELECT
  district AS x_axis,
  ROUND(avg_watt, 1) AS data
FROM env_streetlight_district_summary
WHERE city_scope = $1
ORDER BY avg_watt DESC;
```

### 全區瓦數級距比例圓餅圖

```sql
SELECT
  watt_bucket AS x_axis,
  light_count AS data
FROM env_streetlight_watt_bucket_summary
WHERE city_scope = $1
ORDER BY watt_bucket_order;
```

### 地圖圖層資料

```sql
SELECT
  light_id,
  city,
  district,
  address,
  light_type,
  watt,
  watt_bucket,
  pole_height,
  light_year,
  source_name,
  data_time,
  ST_AsGeoJSON(wkb_geometry)::json AS geometry
FROM env_streetlight_assets
WHERE
  CASE
    WHEN $1 = 'taipei' THEN city = '臺北市'
    WHEN $1 = 'twin_city' THEN city IN ('臺北市', '新北市')
  END
  AND wkb_geometry IS NOT NULL;
```

## 資料端邏輯

資料端需把臺北市與新北市來源資料清理並整合，產出三種輸出表：統一路燈明細表、行政區聚合表、瓦數級距聚合表。

### 臺北市 ETL

1. 從靜態 JSON 下載全量資料。
2. 將 TWD97 (X, Y) 轉換為 WGS84 經緯度（使用 `pyproj` TWD97 EPSG:3826 → WGS84 EPSG:4326）。
3. 展開多燈種欄位：每根燈桿依 `LightKind1–5` / `LightWatt1–5` 的非空組合，展開為多筆燈具記錄，各自帶 `Quantity`（此燈桿燈數）分攤或保留原值。第一版以 `LightKind1` / `LightWatt1` 為主燈種，僅在有 `LightKind2` 時展開第二筆，以此類推。
4. 清理 `LightWatt`：去除單位文字（如 `W`、`w`），轉為 `NUMERIC`；無法解析歸入 `watt=NULL`，`watt_bucket=unknown`。
5. 標準化 `LightKind` → `light_type`：判斷含 `LED` 字樣則標 `led`；含 `鈉` 或 `HPS` 標 `sodium`；含 `複金屬` 或 `metal` 標 `metal_halide`；含 `日光` 或 `fluorescent` 標 `fluorescent`；其他歸 `other`；空值歸 `unknown`。
6. 計算 `watt_bucket`。

### 新北市 ETL

1. 以 `limit=1000` 分頁抓取全量約 28 萬筆資料。
2. 直接使用 `longitude` / `latitude` 欄位，轉 `NUMERIC` 後建立 `wkb_geometry`。
3. 清理 `power` 字串 → `watt NUMERIC`。
4. 無 `LightKind` 欄位，`light_type` 一律填 `unknown`；無 `LightYear` 欄位，`light_year` 填 `NULL`；`height` 多為空，`pole_height` 填 `NULL`。
5. 計算 `watt_bucket`。
6. `address` 若含 `*` 遮蔽字元，保留原字串，地圖彈跳資訊顯示部分遮蔽地址。

### 路燈明細表

建議資料表：`env_streetlight_assets`

| 欄位 | 型別 | 說明 |
|------|------|------|
| `source_name` | text | `臺北市路燈位置分布圖` 或 `新北市路燈資料` |
| `city` | text | `臺北市` 或 `新北市` |
| `district` | text | 行政區 |
| `light_id` | text | 原始路燈 ID（臺北 `SerialNumber`，新北 `seqno`） |
| `light_type` | text | 標準化燈種：`led`, `sodium`, `metal_halide`, `fluorescent`, `other`, `unknown` |
| `watt` | numeric | 清理後瓦數（W），無法解析為 NULL |
| `watt_bucket` | text | 瓦數級距 |
| `watt_bucket_order` | integer | 圖表排序用（1–6 對應 ultra_low 到 unknown） |
| `pole_height` | numeric | 燈桿高度（公尺），nullable |
| `light_year` | integer | 裝設或使用年分，nullable（新北市無此欄位） |
| `address` | text | 路燈地址，nullable（臺北市無此欄位） |
| `longitude` | numeric | WGS84 經度 |
| `latitude` | numeric | WGS84 緯度 |
| `data_time` | timestamptz | 記錄更新時間（臺北 `UpdDate`，新北批次下載時間） |
| `wkb_geometry` | geometry(Point, 4326) | 路燈點位 |

### 行政區聚合表

建議資料表：`env_streetlight_district_summary`

| 欄位 | 型別 | 說明 |
|------|------|------|
| `city_scope` | text | `taipei` 或 `twin_city` |
| `city` | text | `臺北市` 或 `新北市` |
| `district` | text | 行政區 |
| `light_count` | integer | 路燈總數 |
| `avg_watt` | numeric | 行政區路燈平均瓦數（排除 NULL watt） |
| `median_watt` | numeric | 中位數瓦數（輔助指標） |
| `unknown_watt_count` | integer | 瓦數無法解析的路燈數 |
| `data_time` | timestamptz | 資料內容時間 |

聚合規則：
- `avg_watt` 以 `watt IS NOT NULL` 的路燈計算加權平均；`watt_bucket=unknown` 的燈不計入平均，但計入 `unknown_watt_count`。
- `taipei` 範圍只產生臺北市行政區資料；`twin_city` 範圍產生臺北市與新北市行政區資料。
- 每次 ETL 後全量重寫此表（truncate & insert）。

### 瓦數級距聚合表

建議資料表：`env_streetlight_watt_bucket_summary`

| 欄位 | 型別 | 說明 |
|------|------|------|
| `city_scope` | text | `taipei` 或 `twin_city` |
| `watt_bucket` | text | 瓦數級距 |
| `watt_bucket_order` | integer | 圖表排序 |
| `light_count` | integer | 該級距路燈數 |
| `light_ratio` | numeric | 占該 city_scope 全部路燈比例 |
| `data_time` | timestamptz | 資料內容時間 |

### 資料更新與 metadata

ETL 每次更新後需同步更新 `dataset_info`。`env_streetlight_assets` 為地圖圖層主表，`dataset_info` 的 geometry 類型標記為 `Point`，座標系統 `EPSG:4326`。

臺北市 ETL 建議觸發條件：每週定期下載，與靜態檔案 `UpdDate` 最大值比對，有更新才重跑清理；新北市 ETL 每週對齊其開放資料更新頻率。

## AI Chat 的結合方法

AI Chat 透過後端 tool calling 整合本組件，不直接讓前端呼叫資料庫。建議提供以下 tools：

| Tool | 參數 | 回傳 | 用途 |
|------|------|------|------|
| `get_streetlight_summary` | `city_scope` | 路燈總數、平均瓦數、各級距占比、資料時間 | 回答整體能源效率概況 |
| `get_streetlight_district_stats` | `city_scope` | 各行政區 `light_count`, `avg_watt`, `unknown_watt_count` | 供 AI 解釋行政區深淺圖 |
| `get_streetlight_watt_distribution` | `city_scope`, `district?` | 各瓦數級距路燈數與比例 | 供 AI 解釋圓餅圖，支援指定行政區 drill-down |
| `get_streetlight_detail` | `light_id` | 單一路燈城市、行政區、地址、燈種、瓦數、燈桿高、裝設年分、座標 | 供地圖點擊或使用者詢問單盞路燈資訊 |
| `set_streetlight_view` | `city_scope`, `focus_district`, `focus_watt_bucket` | 前端視圖控制指令 | 讓 AI 協助切換臺北/雙北、聚焦行政區或特定瓦數級距 |

Tool 參數規則：

- `city_scope` 只允許 `taipei` 或 `twin_city`。
- `district` 使用行政區中文名稱（如 `中正區`）；未指定時代表全部行政區。
- `light_id` 必須是原始資料的路燈 ID。

AI 回答需附帶資料時間與資料來源，並在資料缺漏時明確說明限制。例如新北市無燈種資料，`light_type` 一律為 `unknown`，AI 應告知使用者此限制；新北市無裝設年分，無法回答老化相關問題。
